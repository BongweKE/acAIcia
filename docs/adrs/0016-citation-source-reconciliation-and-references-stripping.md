# ADR 0016: Citation Source Reconciliation and References Stripping

## Status
Accepted

## Context
In the multi-agent RAG pipeline, the system fetches the top 5 documents from the hybrid retrieval system. However, the Synthesis Agent sometimes only cites a subset of these 5 documents. Previously, the frontend displayed all 5 retrieved documents as source cards regardless of whether they were cited, which confused users (Issue #21).

Additionally, the LLM was explicitly instructed in the streaming prompt (Rule 5) to generate a "References" or "Bibliography" section at the end of its response. Because the frontend independently renders rich Source Cards with DOI links, this trailing text was redundant and cluttered the UI.

## Decision
1. **Strip Trailing References**: We removed Rule 5 from the streaming synthesis prompt and added a post-processing function (`strip_trailing_references`) to cut off any trailing bibliography-like sections generated by the LLM.
2. **Reconcile Sources**: We implemented `reconcile_sources_with_citations` to scan the generated synthesis text for `[Author, Year]` inline citations and match them to the original source metadata.
3. **Frontend Citation Badges**: A `cited` boolean flag is passed to the frontend to visually distinguish between "Cited" sources (used by the LLM) and "Retrieved" sources (fetched but unused). A client-side fallback regex is also included for robustness.

## Consequences
- **Improved UX**: Redundant bibliography text is removed.
- **Transparency**: Users can see exactly which retrieved documents influenced the answer versus those that were simply returned by the database.
- **Complexity**: Adds a regex parsing step at the end of the generation pipeline, which requires careful error handling to prevent false negatives in citation matching.
